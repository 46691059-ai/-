# 数据库版本管理规范

版本：1.0
生效日期：2026-08-03

本规范管理数据库脚本的版本身份、不可变性和发布门禁。具体迁移执行要求同时遵循
`docs/database-migration-rule.md`。

## 1. 历史SQL不可修改

1. 已在共享开发、测试、预发布或生产环境执行的SQL视为已发布历史，禁止修改内容。
2. 历史SQL禁止重命名、覆盖、删除或改变执行顺序。
3. 修复历史问题只能新增更高版本migration，禁止回写旧版本。
4. CI必须记录历史migration的SHA-256；任一摘要变化立即阻断发布。
5. `deprecated`目录只保存历史快照，不参与初始化和升级，也不得重新激活。
6. 全量基线文件一旦随版本发布即冻结；新结构通过migration演进，并在下一个正式基线
   重建Sprint中由迁移结果生成新快照。

Sprint 2-0.2.2完成的聚合V1.0移动和停用标记是其最后一次治理动作，自本规范生效后冻结。

## 2. 新增结构必须使用migration

以下变更必须新增版本migration：

- 新增、修改或删除表/字段；
- 修改字段类型、长度、默认值或可空性；
- 新增或修改主键、唯一键、索引、外键、CHECK约束；
- 结构相关数据回填和编码值域转换；
- 重命名对象；
- 初始化数据中影响授权、字典或业务规则的发布变更。

禁止直接修改生产数据库，禁止只修改Entity后依赖ORM自动建表，禁止用全量初始化脚本覆盖
已部署数据库。

## 3. 版本编号规范

### 3.1 文件格式

```text
V{major}.{minor}.{patch}__{lower_snake_case_description}.sql
```

示例：

```text
V2.0.1__align_project_core_columns.sql
V2.0.2__migrate_project_profit_columns.sql
V2.0.3__add_project_risk_deleted_check.sql
```

### 3.2 编号规则

1. 版本号在整个物理数据库内全局唯一，不按模块重复编号。
2. 新版本必须大于仓库中全部已发布migration版本；当前已有 `V2.0.0`，后续从更高版本开始。
3. `major`用于不兼容的大版本数据库演进；`minor`用于业务域阶段版本；`patch`用于顺序增量。
4. 一个版本只允许一个文件，一个文件只处理一个可独立验收的目标。
5. 描述必须表达动作和对象，不使用 `fix`、`update`、`new` 等无上下文名称。
6. 版本SQL存放在 `database/mysql/migration`；manual、deprecated和init文件不占用migration版本。
7. 达梦、人大金仓脚本使用相同逻辑版本号并存放在各自方言目录，禁止改变业务语义。

## 4. 迁移内容规范

每个migration必须包含或随附：

- 变更目的和关联Sprint；
- 适用Schema和前置版本；
- 结构前置检查；
- DDL和数据迁移；
- 异常数据处理方式；
- 影响行数、锁表、磁盘和执行时间评估；
- 验收SQL；
- 回滚或前向修复方案；
- MySQL、达梦、人大金仓兼容性说明。

结构扩展、数据回填、应用切换、约束收紧和旧结构删除应分版本实施，避免不可逆大爆炸发布。

## 5. 回滚要求

1. 发布前必须完成全量备份并验证能够恢复。
2. 每个migration必须定义回滚触发条件、最晚回滚时间和责任人。
3. 优先使用前向修复；不可逆变更必须有经过演练的数据恢复方案。
4. 删除、重命名、类型收窄前必须保留兼容结构一个观察期。
5. 数据回滚必须核对记录数、业务唯一键、金额汇总和外键完整性。
6. 禁止通过重新执行旧全量脚本回滚生产库。
7. 回滚脚本不得与升级脚本混放并自动执行，应由DBA在审批后受控运行。

## 6. 一致性测试要求

### 6.1 三条路径

每个数据库版本必须验证：

1. 空库执行唯一初始化入口；
2. 上一正式版本执行全部新增migration；
3. 受支持的legacy结构执行迁移链。

三条路径的最终Schema必须一致。

### 6.2 结构检查

通过 `information_schema` 比对：

- 表及视图；
- 字段顺序、类型、长度、默认值和可空性；
- 主键、唯一键、普通索引及字段顺序；
- 外键、CHECK约束；
- 字符集和排序规则。

### 6.3 数据检查

- 迁移前后记录数；
- 重复业务编码和非法空值；
- 孤儿外键；
- 金额和数量汇总；
- 状态、类型和值域分布；
- 异常清单必须为零或有审批结论，禁止静默丢弃。

### 6.4 应用检查

- Spring Boot启动；
- Entity映射报告无差异；
- 受影响Mapper最小增删改查；
- 逻辑删除、唯一键复用和乐观锁；
- 数据权限、安全策略和关键查询计划。

## 7. 发布阻断项

出现以下任一情况不得发布：

- 修改历史SQL或校验和变化；
- 同一活动结构由多个脚本维护；
- 初始化库与升级库结构不同；
- 缺少备份、回滚或恢复演练；
- 迁移存在未处理异常数据；
- Entity、API契约与权威DDL不一致；
- migration未在目标MySQL版本验证；
- 国产数据库差异无记录或无替代方案；
- Project结构与 `05_project.sql` 基线目标不一致且未经正式基线变更审批。
