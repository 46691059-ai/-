## 5. Worker启动门禁

### 5.1 开启条件

Outbox Worker只能在以下条件全部满足后，由授权运维人员在批准窗口开启：

1. 本报告状态已由`NO_GO`正式签署为`GO`；
2. 所有P0阻断项已关闭；
3. 冻结commit、构建产物和配置版本一致；
4. MySQL、Redis、Workflow和Investment健康；
5. Workflow流程版本已固定，账号及节点权限已验证；
6. Token/HMAC握手及Nonce防重放验证通过；
7. Outbox当前积压、失败和死信基线已记录，没有未知历史消息；
8. traceId、指标、日志和告警看板可用；
9. 已指定启用人、批准人、开始时间、结束时间和紧急联系人；
10. 初次只允许单实例、小批量和单条受控测试事项。

开启操作必须通过受控部署配置完成，不直接修改源码或配置文件，不在命令行、日志或工单中输出密钥。

### 5.2 正常关闭条件

- 首次测试流程达到预定暂停点或完成验收；
- 联调窗口结束；
- 无待确认的发送中消息，或消息状态已形成可恢复记录；
- 已保存脱敏证据、traceId、binding、Inbox/Outbox和审计结果；
- 联调负责人确认后将Worker恢复为关闭状态。

### 5.3 异常停止规则

出现以下任一情况必须立即停止Worker并暂停流程办理：

- Workflow流程ID、版本或节点配置与冻结基线不一致；
- Token、签名、时间戳或Nonce校验异常增长；
- 越权、身份映射错误或职责分离失效；
- MySQL/Redis不可用、Schema或Flyway漂移；
- 同一业务重复创建流程、重复推进状态或幂等失效；
- Inbox事件乱序缺口无法补偿、Outbox重试异常或死信增长超阈值；
- Workflow回调与Investment绑定、快照、attemptNo或事件序号不一致；
- 敏感信息出现在日志、响应、报告或监控中；
- 审计、traceId或告警链路失效。

停止后保持现场数据，不执行`clean`、自动`repair`或删除消息；记录停止时间和原因，关闭Worker，阻断新增提交，保存审计证据，并将对应阻断项标记为`REOPENED`。

## 6. 首次联调方案

### 6.1 测试决策准备

1. 创建仅用于非生产联调的独立投资事项和决策，禁止使用生产数据或真实敏感材料。
2. 固定可研、尽调和投资方案版本，生成不可变决策快照。
3. 选择最小但完整的决策路线，明确发起人、审批人、节点和预期结果。
4. 记录decisionId、snapshotId、attemptNo、幂等键和traceId；报告中只使用非敏感标识。
5. 确认同一决策此前没有Workflow binding、待发送Outbox或遗留Inbox事件。

### 6.2 流程启动

1. 完成Go/No-Go签署后，在受控窗口启用单实例Worker。
2. 由真实发起人提交决策，Investment生成且只生成一条待发送事件。
3. 验证Workflow只创建一个流程实例，并返回冻结的定义键和版本。
4. 验证Investment保存唯一binding，decisionId、snapshotId和attemptNo匹配。
5. 验证Outbox成功确认，未发生重复发送或重复实例。

### 6.3 暂停检查点

流程实例创建并生成首个待办后，暂不办理审批：

- 关闭Worker或停止继续发送新的测试消息；
- 核对Investment状态、Workflow实例状态、首节点和任务办理人；
- 核对快照哈希、流程版本、binding、幂等记录和traceId；
- 核对Outbox、Inbox、审计和安全日志中没有敏感信息；
- 确认无重复实例、无越权、无未知积压后，由联调负责人批准继续。

任一检查不通过，保持暂停并执行异常停止规则。

### 6.4 继续审批

1. 在批准后恢复必要的受控发送能力。
2. 由真实审批人查询、签收并办理当前任务，验证候选组和节点权限。
3. 对每个节点核对实际办理人、意见摘要、时间、节点结果和事件序号。
4. 至少覆盖正常通过路线；驳回、撤回和异常路线使用独立测试决策，不复用首个实例强行改写状态。
5. 禁止Controller、数据库脚本或管理员后台直接篡改Investment决策状态。

### 6.5 回调验证

1. 验证Callback Token、HMAC、时间戳、Nonce、请求ID和契约版本。
2. 验证Workflow实例、决策、快照、attemptNo和事件序号绑定一致。
3. 验证Inbox持久化、重复事件去重和乱序事件处理。
4. 验证Investment状态机只发生一次合法流转，审计事件和traceId完整。
5. 验证错误签名、重复Nonce、重复事件和越权回调均被拒绝且不推进业务状态。

### 6.6 收尾

1. 核对Workflow最终状态、Investment决策状态及节点摘要一致。
2. 核对Outbox无未知积压、Inbox无未解释缺口、死信和重放记录符合预期。
3. 关闭Worker，保留脱敏证据并清理隔离测试数据。
4. 对正常、驳回、撤回、异常、重复和乱序场景分别形成结果，不以单一路径代表全部通过。
5. 只有全部场景真实执行并通过后，才更新Sprint 2-3.7联调报告。
