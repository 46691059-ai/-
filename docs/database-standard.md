# 数据库开发规范

版本：V1.0.0

## 1. 命名与字段

- 表名使用小写英文和下划线，格式为 `模块_业务名称`。
- 字段使用小写英文和下划线；主键统一为 `id BIGINT`。
- 标准业务表保留 `create_time`、`create_by`、`update_time`、`update_by`、`deleted`、`delete_token`、`remark`、`version`。
- 逻辑删除值：有效为 0，删除为 1；唯一键需要与删除占位字段配合。
- 金额使用 `DECIMAL`，时间使用 `DATETIME`，状态值应有字典或代码约束。

## 2. 主键、索引与约束

- 应用侧主键由 MyBatis Plus 统一生成；禁止业务代码依赖连续主键。
- 高频过滤、关联和排序字段必须评估联合索引；联合索引遵循最左前缀。
- 唯一业务编码必须有唯一索引，仅做 Service 查询不能替代数据库约束。
- 外键仅在现有设计允许时使用；新增外键须评估初始化顺序、逻辑删除和批处理影响。
- 禁止在索引列上进行导致索引失效的函数计算和隐式类型转换。

## 3. Entity 与 Mapper

- Entity 字段必须与真实表字段一一对应，驼峰映射到下划线。
- 标准实体继承 `BaseIdEntity`；特殊历史表必须明确说明差异。
- Mapper 继承统一 Mapper 基类，仅负责数据访问，不包含业务判断。
- 启动映射检查发现差异时必须输出报告；生产发布前核心表差异必须为零。

## 4. SQL 与迁移

- 初始化/迁移 SQL 按文件编号顺序执行；已执行脚本不得原地修改语义。
- 生产变更先备份、后迁移、再核查，并准备可执行的回滚或前向修复方案。
- 动态条件必须参数化，禁止字符串拼接用户输入。
- 大表更新、删除和索引创建必须评估锁表、日志量和执行窗口。
- MySQL 专属写法需注明；迁移达梦、人大金仓时提供对应方言脚本。
