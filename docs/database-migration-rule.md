# 数据库版本迁移规范

版本：1.0
生效日期：2026-08-03

## 1. 适用范围

本规范适用于MySQL生产数据库的结构、约束、索引和初始化数据变更。达梦、人大金仓适配
脚本必须遵循相同版本语义，并提供独立方言实现和一致性验证。

全量初始化快照用于新库，版本迁移用于已部署数据库。两者职责分离，禁止用覆盖全量脚本
代替生产迁移。

## 2. 版本迁移规则

1. 每个已发布数据库变更必须使用独立、单向、不可变的版本脚本。
2. 文件命名统一为：

   ```text
   V{major}.{minor}.{patch}__{lower_snake_case_description}.sql
   ```

3. 版本号必须全局唯一并严格递增，不得按模块分别复用同一版本。
4. 一个迁移只处理一个可独立验证的目标；结构增加、数据回填、约束收紧和旧列清理原则上
   分为不同版本。
5. 脚本必须明确适用数据库、前置版本、影响表、锁表风险、预计耗时和回滚方案。
6. 迁移必须由受控流水线或DBA工具执行，并记录版本、校验和、执行人、开始/结束时间和结果。
7. 禁止应用启动时自动执行未经审批的生产DDL。
8. 跨模块外键由引用方提出、双方评审，并在独立迁移中建立；不得在两个模块快照中重复定义同一表。

## 3. 历史migration不可变规则

1. 已在任何共享环境执行的migration禁止修改、重命名、替换或删除。
2. 修复历史迁移必须新增更高版本的前向修复脚本。
3. CI必须保存并校验历史脚本摘要；摘要变化直接阻断构建。
4. `deprecated`快照不是migration，不得重新移回自动执行入口。
5. 注释说明不能替代可执行的数据迁移和校验步骤。

## 4. 新增版本方式

新增迁移必须按以下流程：

1. 从真实环境只读导出 `information_schema`，确认起始结构；
2. 编写变更设计、数据影响分析和回滚设计；
3. 新增版本SQL，不修改历史脚本；
4. 在生产数据脱敏副本或等量级预发布环境演练；
5. 执行结构、数据、性能和应用回归；
6. 完成DBA、安全、模块负责人评审；
7. 备份并验证可恢复后执行生产变更；
8. 保存执行日志和验收报告。

推荐采用“扩展—迁移—收敛”模式：

```text
新增兼容字段/表
  -> 分批回填数据
  -> 应用切换并观察
  -> 收紧约束
  -> 独立版本清理旧结构
```

## 5. SQL编写要求

- 明确使用 `USE enterprise_platform` 或由迁移工具锁定目标Schema；
- DDL前验证目标表和关键列状态，状态不符合预期时快速失败；
- 大表新增索引和字段必须评估在线DDL、锁等待、磁盘和复制延迟；
- 禁止无条件删除表、列或历史数据；
- 数据回填必须可分批、可重入、可核对，不得静默跳过异常数据；
- 唯一键、外键、NOT NULL和CHECK约束应在数据清洗后增加；
- 敏感数据不得写入迁移日志；
- MySQL专属语法必须标注，并为国产数据库迁移准备替代实现。

## 6. 回滚要求

每个迁移必须提供可操作的回滚说明，至少包含：

1. 回滚触发条件；
2. 回滚截止点；
3. 应用版本兼容范围；
4. 数据恢复来源和校验方法；
5. DDL逆操作或前向修复脚本；
6. 负责人和预计恢复时间。

生产环境原则上优先采用前向修复。涉及删除、重命名、类型缩窄或不可逆数据转换时，必须
先完成全量备份和恢复演练，并保留旧结构一个观察期。回滚不得仅依赖“重新运行旧脚本”。

## 7. 一致性测试要求

每个版本必须至少验证：

### 7.1 结构一致性

- 从空库执行全量初始化后结构符合权威快照；
- 从上一正式版本执行migration后，最终结构与空库初始化结果一致；
- 比对字段、类型、默认值、可空性、索引、主键、唯一键、外键和检查约束；
- Entity与最终数据库字段映射一致。

### 7.2 数据一致性

- 迁移前后核心表记录数；
- 业务唯一键重复和空值；
- 孤儿外键；
- 金额、数量和状态分布汇总；
- 异常数据清单数量及处理结果；
- 抽样记录或受控哈希核验。

### 7.3 应用回归

- Spring Boot启动和数据库映射检查；
- 受影响Mapper最小增删改查；
- 逻辑删除、唯一键复用和乐观锁；
- 数据权限和资源访问策略；
- 关键查询执行计划和性能基线。

### 7.4 CI阻断条件

以下任一情况必须阻断发布：

- 历史migration校验和变化；
- 同一表在两个活动快照中重复定义；
- 新库初始化和升级库最终结构不同；
- 数据迁移存在未归档异常记录；
- 缺少备份、回滚或恢复演练；
- Entity与权威DDL字段不一致；
- SQL未经目标MySQL版本及国产数据库兼容性评估。

## 8. Project模块专项规则

- `database/mysql/05_project.sql` 是当前Project全量结构快照；
- `database/mysql/deprecated/V1.0.0__enterprise_platform_v1.sql` 只用于历史识别；
- 新的Project结构变更只能新增版本migration，不得继续编辑聚合V1.0；
- `project_profit` 统一使用 `total_income`、`total_cost`、`calculate_date`；
- 生产迁移前必须执行 `docs/project-database-baseline.md` 中的结构识别方案。
